دليل نظم إدارة قواعد البيانات (DBMS) الشامل

المرجع الهندسي المتكامل لتصميم، هيكلة، وإدارة أنظمة قواعد البيانات ومحركات التخزين والتزامن.

إعداد الكاتبة والمهندسة: مها شهوب

01. مفهوم نظم إدارة قواعد البيانات DBMS

تعريف النظام البرمجي الوسيط الذي يتحكم في إنشاء، تنظيم، قراءة، وتحديث البيانات بأمان.

-- النظام يدير التواصل بين التطبيق وملفات التخزين الفيزيائية
SELECT 'DBMS Architecture Initialized' AS status;

02. تطور وتاريخ هندسة قواعد البيانات

التحول من الملفات النصية المسطحة والأنظمة الهرمية إلى النماذج العلائقية والحديثة.

-- الانتقال التاريخي من Flat Files إلى Relational Models في السبعينيات

03. الهندسة ثلاثية المستويات لـ ANSI-SPARC

فصل مستويات النظام إلى الداخلي (Internal)، المفاهيمي (Conceptual)، والخارجي (External).

-- ضمان استقلال البيانات عبر حجب البنية الفيزيائية عن المستخدم النهائي

04. استقلال البيانات المنطقي والفيزيائي

القدرة على تعديل بنية البيانات الداخلية أو الخارجية دون الحاجة لتعديل التطبيقات البرمجية.

-- Logical Data Independence vs Physical Data Independence

05. مكونات هندسة نظام DBMS الأساسية

مُحلل الاستعلامات، مُحسن الخطط، مدير التخزين، مدير المعاملات، ومدير السجلات.

-- Query Processor + Storage Manager + Transaction Manager

06. نموذج البيانات الهرمي (Hierarchical)

تنظيم البيانات على شكل شجرة تترابط فيها السجلات بعلاقة الأب والابن (Parent-Child).

-- نموذج يعتمد على روابط تشعبية صارمة باتجاه واحد

07. نموذج البيانات الشبكي (Network)

تطوير للنموذج الهرمي يتيح للأب الواحد امتلاك أبناء متعددين، وللابن امتلاك آباء متعددين.

-- استخدام المؤشرات (Pointers) لربط السجلات العقدية

08. النموذج العلائقي Relational Model

النموذج الرياضي لإدгар البيانات في جداول ثنائية الأبعاد (صفوف وأعمدة) أسسه إدگار كود.

CREATE TABLE relations_model (id INT PRIMARY KEY, attribute_name VARCHAR(50));

09. نموذج الكيان والعلاقة ER Diagram

التصميم الرسومي المسبق لتحديد الكيانات (Entities)، الخصائص (Attributes)، والعلاقات.

-- تحويل مخططات ER إلى جداول ومفاتيح أجنبية فعلية

10. خصائص الجداول والصفوف والأعمدة

التجانس الرياضي، عدم أهمية ترتيب الصفوف، وفرادة أسماء الأعمدة داخل الجدول الواحد.

SELECT COLUMN_NAME FROM INFORMATION_SCHEMA.COLUMNS WHERE TABLE_NAME = 'users';

11. قيود النزاهة التكاملية Integrity Constraints

القواعد التي تضمن صحة وسلامة البيانات مثل مفتاح الأساس، القيود الفريدة، وفحص الشروط.

ALTER TABLE accounts ADD CONSTRAINT chk_balance CHECK (balance >= 0);

12. مفاهيم لغة التعريف DDL

مجموعة الأوامر المسؤولة عن إنشاء وتعديل وهندسة هياكل الكيانات (CREATE, ALTER, DROP).

CREATE TABLE schema_definition (id INT);

13. مفاهيم لغة المعالجة DML

أوامر إدارة محتوى الجداول وإدخال واسترجاع وتحديث وحذف السجلات (SELECT, INSERT, UPDATE, DELETE).

INSERT INTO schema_definition VALUES (1);

14. مفاهيم لغة التحكم DCL & TCL

أوامر إدارة الصلاحيات (GRANT, REVOKE) والتحكم بالمعاملات (COMMIT, ROLLBACK).

GRANT SELECT ON db.* TO 'user'@'localhost';

15. مقدمة في الجبر العلائقي Relational Algebra

الأساس الرياضي النظري لعمليات الاستعلام ومعالجة الجداول في نظم DBMS.

-- العمليات الأساسية: Selection, Projection, Union, Set Difference, Cartesian Product

16. عمليات الانتقاء والاسقاط (Select & Project)

الانتقاء (فلاتر الصفوف بشروط) والإسقاط (تحديد أعمدة معينة دون غيرها رياضياً).

SELECT name FROM employees WHERE salary > 5000;

17. عمليات الربط الديكارتي والتقاطع

دمج مجموعتين رياضياً واستخراج العناصر المشتركة أو ضرب المجموعات.

SELECT * FROM table1 CROSS JOIN table2;

18. تطبيع قواعد البيانات Normalization الأساسي

المنهجية الهندسية للقضاء على التكرار والشذوذ في الإدخال والحذف والتحديث.

-- القضاء على Anomalies (Insertion, Update, Deletion Anomalies)

19. الصيغة الطبيعية الأولى 1NF

اشتراط أن تكون قيم الأعمدة ذرية (Atomic) وغير مركبة أو متعددة القيم.

-- فصل القيم المتعددة في خلايا مستقلة لصفوف جديدة

20. الصيغة الطبيعية الثانية 2NF

تحقيق الصيغة الأولى مع خلو الجدول من الاعتماد الجزئي على جزء من المفتاح المركب.

-- الاعتماد التام لجميع الأعمدة على المفتاح الأساسي كاملاً

21. الصيغة الطبيعية الثالثة 3NF

تحقيق الصيغة الثانية وإزالة الاعتماديات المتعدية (Transitive Dependencies) بين الأعمدة غير المفتاحية.

-- يجب ألا يعتمد عمود غير مفتاحي على عمود غير مفتاحي آخر

22. صيغة بويس-كود Boyce-Codd NF

صيغة أكثر صرامة من الثالثة، تشترط أن يكون كل محدد (Determinant) مفتاحاً رئيسياً.

-- BCNF حل لحالات شاذة لا تعالجها الصيغة الثالثة وحدها

23. الاعتمادات الوظيفية Functional Dependencies

العلاقة الرياضية التي يحدد فيها عمود (أو مجموعة أعمدة) قيمة عمود آخر بفرادة تامة.

-- X -> Y (معرفة X تؤدي بالضرورة لمعرفة Y بدقة)

24. فك التطبيع Denormalization ومبرراته

إعادة دمج بعض الجداول عمداً لتحسين أداء سرعة الاستعلامات وتقليل عمليات الربط (JOINs) المكلفة.

-- استخدام Denormalization بحذر لرفع كفاءة قراءة البيانات الضخمة

25. إدارة المعاملات Transactions وعيوب التزامن

معالجة المشاكل الناتجة عن تداخل تنفيذ العمليات المتزامنة (Lost Update, Dirty Read).

START TRANSACTION;
-- تنفيذ أوامر مالية متزامنة
COMMIT;

26. خصائص المعاملات الخمسة ACID Properties

الذرية (Atomicity)، الاتساق (Consistency)، العزلة (Isolation)، والمتانة (Durability).

-- ضمان التزام نظام DBMS بهذه المعايير لسلامة البيانات المطلقة

27. جداول الجدولة والتزامن Concurrency Control

تنظيم تنفيذ العمليات المتداخلة بطريقة قابلة للتسلسل (Serializability) لضمان صحة النتائج.

-- Conflict Serializability & View Serializability

28. البروتوكولات القائمة على القفل Locking Protocols

آليات التحكم في قفل البيانات المشتركة (Shared Locks و Exclusive Locks) لمنع التضارب.

LOCK TABLES accounts WRITE;
-- تنفيذ العمليات
UNLOCK TABLES;

29. قفل المرحلتين Two-Phase Locking (2PL)

بروتوكول يضمن القابلية للتسلسل عبر مرحلتين: مرحلة نمو الأقفال ومرحلة تحريرها.

-- Strict 2PL & Rigorous 2PL لضمان عدم حدوث Dirty Reads

30. مشكلة التعارض الميت Deadlocks وإدارتها

الحالة التي تنتظر فيها معاملتان تحرير أقفال تمتلكها كل منهما، وكيفية كشفها وحلها.

SHOW ENGINE INNODB STATUS; -- مراقبة حالات Deadlock في محركات InnoDB

31. طوابع الزمن Timestamp-based Protocols

تنظيم أولوية تنفيذ المعاملات باستخدام طوابع زمنية فريدة تمنع التعارض دون أقفال.

-- Thomas's Write Rule وتنظيم طوابع قراءة وكتابة البيانات

32. إدارة الاسترجاع والتعافي Recovery System

قدرة نظام DBMS على إعادة القاعدة لحالة سليمة بعد انقطاع التيار الكهربائي أو انهيار النظام.

-- ARIES Algorithm للتعافي الفعال القائم على السجلات

33. سجل المعاملات Write-Ahead Logging (WAL)

كتابة التغييرات في سجل العمليات على القرص الصلب قبل تعديل البيانات الفعلية لضمان الاسترجاع.

-- ضمان عدم ضياع أي معاملة تمت الموافقة عليها (Commit)

34. آليات الاسترداد بالحفظ الاحتياطي Checkpoints

حفظ الحالة الراهنة للذاكرة على القرص بشكل دوري لتسريع عمليات التعافي لاحقاً.

-- تقليل الوقت اللازم لمسح سجلات WAL عند إعادة التشغيل

35. تجميع الصفحات والتخزين المؤقت Buffer Management

إدارة الذاكرة العشوائية (RAM) ونقل صفحات البيانات بين القرص والذاكرة عبر خوارزميات الاستبدال.

-- خوارزميات مثل LRU (Least Recently Used) لإدارة Buffer Pool

36. هياكل التخزين الفيزيائي للملفات

كيفية تنظيم الملفات والكتل (Blocks) على الأقراص الصلبة وإدارتها بواسطة النظام.

-- Fixed-Length Records vs Variable-Length Records Storage

37. تنظيم الملفات وتخزين السجلات

طرق ترتيب السجلات داخل الملفات (Heap Files, Sequential Files, Hashed Files).

-- تنظيم التخزين المتسلسل وغير المنظم لرفع كفاءة الإدخال

38. أساسيات فهرسة البيانات Indexing Structures

بناء هياكل بيانات مساعدة لتسريع عملية البحث عن السجلات دون مسح الجدول بالكامل.

CREATE INDEX idx_employee_name ON employees(name);

39. الفهارس كثيفة التوزيع Dense & Sparse Indexes

الفرق بين فهرسة كل سجل على حدة (Dense) أو فهرسة مفاتيح كتل البيانات الرئيسية (Sparse).

-- Primary Index vs Secondary Index مقارنة الأداء والمساحة

40. أشجار البحث الثنائية B-Trees و B+ Trees

الهيكل الأساسي والأكثر شهرة في فهارس قواعد البيانات لضمان سرعة البحث والتحديث.

-- B+ Tree تحفظ البيانات في الأوراق وتسمح بالبحث المتسلسل السريع

41. التجزئة القائمة Hashing في التخزين

استخدام دال تجزئة لتحديد موقع التخزين المباشر للسجل عبر مفتاحه الفريد.

-- Static Hashing vs Dynamic Hashing (Extendable Hashing)

42. محرك تحسين الاستعلامات Query Optimizer

المكون الذكي في DBMS الذي يحلل الاستعلام ويختار أفضل خطة تنفيذ أقل كلفة واستهلاكاً.

EXPLAIN FORMAT=JSON SELECT * FROM employees WHERE id = 10;

43. تكلفة تنفيذ الاستعلامات واستراتيجيات الخطط

حساب تكلفة الإدخال، القراءة، التخزين المؤقت، وعمليات الفحص (Table Scan vs Index Scan).

-- تقييم I/O Cost و CPU Cost لكل خططة تنفيذ مقترحة

44. محرك قواعد البيانات العلائقية المفتوح MySQL/MariaDB

دراسة هندسة محرك InnoDB واستخداماته الواسعة في الويب وإدارة البيانات.

SHOW ENGINES; -- استعراض المحركات المدعومة

45. محرك قواعد البيانات المؤسسي PostgreSQL

استعراض بنية PostgreSQL المتقدمة، دعمها لأنواع بيانات معقدة ولغات البرمجة والوظائف.

SELECT version(); -- فحص إصدار النظام المؤسسي

46. معمارية قواعد البيانات الموزعة Distributed DBMS

توزيع البيانات ومعالجتها عبر خوادم متعددة جغرافياً بطريقة تبدو وكأنها قاعدة مركزية واحدة.

-- Homogeneous DDBMS vs Heterogeneous DDBMS

47. تجزئة البيانات والنسخ المتماثل Replication

توزيع الجداول أفقياً أو عمودياً (Sharding & Partitioning) ونسخ البيانات لمواجهة الأعطال.

-- Master-Slave Replication vs Multi-Master Replication

48. قواعد البيانات السحابية Cloud Databases

إدارة قواعد البيانات كخدمة (DBaaS) على المنصات السحابية الكبرى مع مرونة التوسيع التلقائي.

-- مرونة التوسيع العمودي والأفقي (Vertical & Horizontal Scaling)

49. قواعد البيانات غير العلائقية NoSQL ومحركاتها

أنظمة إدارة البيانات المرنة المستندة إلى الوثائق، الأزواج، والمخططات الحرة (MongoDB, Cassandra).

// مثال مستند JSON في NoSQL
{ "name": "مها شهوب", "role": "مهندسة قواعد بيانات", "active": true }

50. مقارنة هندسية بين SQL و NoSQL

تحليل نظرية CAP Theorem والفرق بين قواعد ACID و BASE في إدارة البيانات الضخمة.

-- Consistency, Availability, Partition Tolerance (CAP Theorem)

51. أمان قواعد البيانات وحماية الخصوصية

تأمين الوصول، منع الهجمات، وإدارة الثغرات الأمنية في أنظمة DBMS.

-- حماية مشددة ضد ثغرات SQL Injection عبر Prepared Statements

52. تشفير البيانات في الذاكرة وعلى الأقراص

تطبيق آليات التشفير التام (Transparent Data Encryption - TDE) لحماية الملفات السرية.

-- تشفير الملفات الفيزيائية على القرص لمنع القراءة غير المصرحة

53. التحكم في الوصول المستند إلى الأدوار RBAC

منح الصلاحيات للمستخدمين عبر أدوار وظيفية محددة بدلاً من الصلاحيات الفردية المعقدة.

CREATE ROLE 'db_analyst';
