من الجداول والعلاقات والاستعلامات إلى Forms وReports وSQL وVBA وبناء قواعد بيانات عملية.

01 — مقدمة Microsoft Access

Microsoft Access هو نظام إدارة قواعد بيانات علائقية RDBMS يجمع بين تخزين البيانات وتصميم الجداول والعلاقات وإنشاء الاستعلامات والنماذج والتقارير والأتمتة باستخدام Macros وVBA.

الفكرة الأساسية: لا تبدأ من شكل النموذج؛ ابدأ بتحديد البيانات والعلاقات وقواعد العمل، ثم ابنِ الواجهات فوق تصميم قاعدة بيانات صحيح.

02 — ما هو Access؟

يستخدم Access لبناء تطبيقات قواعد بيانات صغيرة ومتوسطة داخل ملف قاعدة بيانات، مع إمكانية ربطه بمصادر خارجية مثل SQL Server.

Tables

Forms
واجهات الإدخال والتشغيل.
Reports
تقارير وطباعة.

04 — Database وTables

قاعدة البيانات Database هي الحاوية المنطقية للبيانات والكائنات. أهم كائن تخزين هو Table. صمّم كل جدول حول كيان واضح مثل Students أو Employees أو Products.

Students
ID | Name | City | Grade | ClassID

Classes
ID | ClassName | Room

05 — الحقول Field

الحقل Field هو عمود يمثل خاصية من خصائص الكيان. مثال: StudentID، StudentName، BirthDate، Phone.

اختر اسمًا واضحًا وثابتًا، وحدد نوع البيانات والحجم المناسب، ولا تضع عدة معلومات مختلفة داخل حقل واحد.

06 — السجلات Records

السجل Record هو صف يمثل حالة واحدة من الكيان. في جدول الطلاب يمثل كل Record طالبًا واحدًا.

قاعدة مهمة: الحقول تصف الشيء، والسجلات تمثل الأشياء.

08 — Primary Key

المفتاح الأساسي Primary Key يميز كل سجل بشكل فريد. غالبًا يستخدم AutoNumber لمعرف داخلي.

StudentID: AutoNumber
Primary Key: StudentID

لا تجعل الاسم أو رقم الهاتف مفتاحًا أساسيًا إذا كان يمكن أن يتكرر أو يتغير.

09 — إنشاء الجداول

في Table Design حدد اسم الحقل، Data Type، الخصائص، ثم اختر Primary Key. أنشئ جدولًا مستقلًا لكل كيان رئيسي.

مثال: لا تكرر اسم الصف واسم المعلم في كل سجل طالب؛ أنشئ جداول مستقلة واربطها بالمفاتيح.

10 — العلاقات Relationships

العلاقة تربط جدولين عبر Primary Key وForeign Key. فعّل Referential Integrity لمنع السجلات اليتيمة عندما تكون قواعد العمل تسمح بذلك.

Classes.ID  (Primary Key)
        ↓
Students.ClassID (Foreign Key)

11 — One-to-One

كل سجل من جدول يرتبط بسجل واحد من جدول آخر. تستخدم عند فصل بيانات نادرة أو حساسة أو عند وجود سبب تصميمي واضح.

12 — One-to-Many

أكثر العلاقات شيوعًا: صف واحد يحتوي عدة طلاب. المفتاح الأساسي في الجدول الأول يظهر كـ Foreign Key في الجدول الثاني.

13 — Many-to-Many

لا تمثل مباشرة بحقل واحد؛ استخدم جدولًا وسيطًا Junction Table.

Students
StudentID | Name

Courses
CourseID | CourseName

StudentCourses
StudentID | CourseID | EnrollDate

14 — Queries

الاستعلام Query يحدد البيانات التي تريد عرضها أو تحليلها أو تعديلها. الأنواع تشمل Select وParameter وAction Queries.

15 — Select Query

SELECT * FROM Students;

لعرض حقول محددة:

SELECT ID, Name, Grade
FROM Students;

16 — Parameter Query

يسمح للمستخدم بإدخال قيمة قبل تشغيل الاستعلام.

PARAMETERS pCity Text (255);
SELECT *
FROM Students
WHERE City=[pCity];

17 — Action Queries

تغير البيانات أو تنشئ جدولًا جديدًا. أهمها Append وUpdate وDelete وMake-Table. استخدمها بحذر، ويفضل تجربة Select أولًا قبل تنفيذ التعديل.

18 — Append Query

INSERT INTO ArchiveStudents (ID, Name, Grade)
SELECT ID, Name, Grade
FROM Students
WHERE GraduationYear=2026;

19 — Update Query

UPDATE Students
SET Grade = Grade + 5
WHERE Grade < 50;

20 — Delete Query

DELETE FROM Students
WHERE ID=10;
DELETE يحذف السجلات. تأكد من شرط WHERE وخذ نسخة احتياطية قبل العمليات الحساسة.

21 — Make-Table Query

SELECT *
INTO Graduates2026
FROM Students
WHERE GraduationYear=2026;

22 — SQL داخل Access

يمكن فتح SQL View وكتابة الاستعلام مباشرة. Access يستخدم صياغة SQL خاصة به في بعض التفاصيل، لذلك اختبر الاستعلام داخل إصدار Access المستخدم.

23 — SELECT

SELECT Name, City, Grade
FROM Students;

24 — WHERE

SELECT Name, Grade
FROM Students
WHERE Grade >= 50;

يمكن استخدام AND وOR وLIKE وIS NULL وBETWEEN.

25 — ORDER BY

SELECT Name, Grade
FROM Students
ORDER BY Grade DESC, Name ASC;

26 — GROUP BY

SELECT City, Count(*) AS Total
FROM Students
GROUP BY City;

27 — JOIN

SELECT Students.Name, Classes.ClassName
FROM Students
INNER JOIN Classes
ON Students.ClassID = Classes.ID;

يمكن استخدام INNER JOIN وLEFT JOIN بحسب البيانات التي تريد الاحتفاظ بها من الطرف الأيسر.

28 — Forms

Form هو واجهة للتعامل مع البيانات. يمكن أن يكون Bound Form مرتبطًا بجدول/استعلام أو Unbound Form للواجهة والتنقل والعمليات.

29 — إنشاء النماذج

اختر مصدر البيانات، أضف الحقول، اضبط التخطيط، ثم أضف أزرار الحفظ والإضافة والبحث والتنقل.

30 — Controls

أهم Controls: Text Box، Label، Combo Box، List Box، Check Box، Option Button، Command Button، Subform، Image.

31 — ComboBox

يستخدم لاختيار قيمة من قائمة، مثل اختيار ClassID مع عرض اسم الصف بدلًا من رقم المفتاح.

الأفضل أن يخزن ComboBox المفتاح، بينما يعرض للمستخدم الوصف المفهوم.

32 — ListBox

مفيد لعرض قائمة عناصر، وقد يسمح باختيار عنصر واحد أو عدة عناصر بحسب إعدادات التحكم.

33 — Buttons

الأزرار تنفذ أوامر مثل فتح نموذج، حفظ سجل، إضافة سجل، طباعة تقرير، أو تشغيل استعلام.

Private Sub btnStudents_Click()
    DoCmd.OpenForm "frmStudents"
End Sub

34 — Reports

Reports مخصصة للعرض والطباعة والتجميع. اربط التقرير باستعلام مناسب بدل وضع منطق معقد داخل التقرير.

35 — تصميم التقارير

استخدم Report Header وPage Header وDetail وGroup Header/Footer وPage Footer. أضف Count وSum وAvg عند الحاجة.

=Sum([Amount])
=Count([StudentID])
=Avg([Grade])

36 — العلاقات المتقدمة

قبل إنشاء العلاقة حدد PK وFK وتأكد من توافق نوع البيانات. فعّل Cascade Update/Delete فقط عندما تكون لهما قاعدة عمل واضحة.

37 — Validation Rules

Validation Rule تمنع إدخال قيم غير مناسبة.

الهدفRule
درجة من 0 إلى 100Between 0 And 100
مبلغ غير سالب>=0
إلزاميIs Not Null

38 — Input Mask

Input Mask تساعد في فرض نمط إدخال محدد مثل أرقام الهاتف أو التاريخ. لا تعتبرها بديلًا كاملًا للتحقق من صحة البيانات.

39 — Indexes

الفهارس تسرّع البحث والفرز والربط في الحالات المناسبة، لكنها تزيد حجم التخزين وكلفة عمليات الإدخال والتعديل. لا تفهرس كل عمود عشوائيًا.

40 — Navigation Forms

أنشئ شاشة رئيسية تحتوي أزرارًا للوصول إلى الطلاب والمبيعات والتقارير والإعدادات. اجعل الواجهة واضحة ومحدودة الصلاحيات.

41 — Subforms

Subform يعرض سجلات مرتبطة بالسجل الرئيسي، مثل نموذج طالب رئيسي مع قائمة المواد المسجل بها.

42 — Macros

Macros تسمح بأتمتة إجراءات دون كتابة VBA في بعض السيناريوهات. يمكن استخدامها لفتح Forms وReports وتشغيل Queries وإظهار الرسائل.

43 — VBA في Access

VBA يضيف منطقًا برمجيًا للأحداث والنماذج والتقارير وقواعد البيانات.

Private Sub btnSave_Click()
    If IsNull(Me.txtName) Then
        MsgBox "أدخل اسم الطالب"
        Exit Sub
    End If
    DoCmd.RunCommand acCmdSaveRecord
    MsgBox "تم الحفظ"
End Sub

49 — DAO

DAO هو الخيار الشائع للتعامل البرمجي مع قاعدة Access ومجموعات Recordset.

Dim rs As DAO.Recordset
Set rs = CurrentDb.OpenRecordset("Students")

rs.AddNew
rs!Name = "أحمد"
rs!Grade = 88
rs.Update

rs.Close
Set rs = Nothing

50 — ADO

ADO يمكن استخدامه للتعامل مع مصادر بيانات مختلفة عبر مزودات مناسبة. في تطبيقات Access الحديثة، DAO غالبًا هو المسار الأبسط عند التعامل مع بيانات Access نفسها.

51 — معالجة الأخطاء

Private Sub btnRun_Click()
On Error GoTo ErrHandler

    CurrentDb.Execute "UPDATE Students SET Grade=Grade+1", dbFailOnError
    MsgBox "تم التنفيذ"
    Exit Sub

ErrHandler:
    MsgBox "حدث خطأ: " & Err.Description
End Sub

52 — البحث داخل قاعدة البيانات

يمكن البحث عبر Query بمعامل، أو ComboBox، أو مربع بحث مرتبط باستعلام.

SELECT *
FROM Students
WHERE Name Like "*" & [أدخل الاسم] & "*";

53 — تسجيل الدخول والصلاحيات

يمكن بناء شاشة Login داخل Access تعتمد على Users Table، مع تحديد Role مثل Admin وUser. لكن لا تتعامل مع هذا على أنه بديل لنظام أمان مؤسسي قوي، خصوصًا للبيانات الحساسة.

Users
UserID | Username | PasswordHash | Role | IsActive
لا تخزن كلمات المرور كنص صريح. في الأنظمة الحساسة استخدم بنية مصادقة مناسبة مثل SQL Server/Active Directory أو تطبيق ويب متخصص.

54 — النسخ الاحتياطي

احتفظ بنسخ دورية من ملف قاعدة البيانات، ويفضل نسخ متعددة في مواقع منفصلة. اختبر استعادة النسخة الاحتياطية بدل افتراض أنها صالحة.

55 — Compact & Repair

الأمر Compact and Repair Database يساعد في تقليل حجم الملف وإصلاح بعض المشكلات الداخلية. نفذه وفق سياسة صيانة واحتفظ بنسخة احتياطية قبل العمليات المهمة.

56 — استيراد Excel

يمكن استيراد ورقة Excel إلى جدول Access، مع مراجعة أنواع البيانات والمفاتيح والتكرارات بعد الاستيراد.

57 — تصدير Excel

يمكن تصدير جدول أو Query أو Report إلى Excel للتحليل أو المشاركة.

58 — ربط Access بـ Excel

يمكن ربط بيانات Excel كمصدر خارجي أو استخدام Access كطبقة بيانات وتنظيم العلاقات والاستعلامات ثم تصدير النتائج.

59 — ربط Access بـ SQL Server

في الأنظمة التي تحتاج تعدد مستخدمين أكبر أو إدارة مركزية للبيانات، يمكن إبقاء Forms/Reports في Access وربط الجداول الخلفية بـ SQL Server عبر Linked Tables أو حلول أخرى.

60 — مشروع إدارة الطلاب

مشروع عملي يتكون من:

  • Students
  • Classes
  • Subjects
  • Grades
  • Teachers
Students(StudentID, Name, ClassID)
Classes(ClassID, ClassName)
Subjects(SubjectID, SubjectName)
Grades(GradeID, StudentID, SubjectID, Grade)

61 — مشروع الموظفين

Employees + Departments + Jobs + Attendance + Salaries. استخدم DepartmentID كمفتاح أجنبي بدل تكرار اسم القسم في كل سجل.

62 — مشروع المبيعات

Customers + Products + Invoices + InvoiceDetails. اجعل الفاتورة رأسًا وتفاصيلها في جدول مستقل لعلاقة One-to-Many.

Invoices(InvoiceID, CustomerID, InvoiceDate)
InvoiceDetails(DetailID, InvoiceID, ProductID, Qty, UnitPrice)

63 — مشروع المخزون

Products + Categories + Suppliers + Purchases + Sales + StockTransactions. يفضل تسجيل حركة المخزون بدل تعديل رقم المخزون عشوائيًا فقط.

64 — مشروع المكتبة

Books + Authors + Members + Borrowings + Categories. علاقة الكتاب والمؤلف قد تكون Many-to-Many، لذلك استخدم BookAuthors كجدول وسيط.

65 — مشروع تسجيل الدخول

أنشئ Users وRoles ثم Form Login وMain Navigation. بعد نجاح المصادقة، افتح الواجهة المناسبة للدور.

68 — تحسين الأداء

  • اختر أنواع بيانات مناسبة.
  • استخدم Indexes للحقول التي تستفيد فعليًا.
  • قلل الاستعلامات غير الضرورية.
  • تجنب تخزين البيانات المكررة.
  • قسم قاعدة البيانات إلى Front-End وBack-End في البيئات متعددة المستخدمين.
  • استخدم SQL Server عندما تتجاوز احتياجات Access المناسبة.

69 — حماية قاعدة البيانات

استخدم أقل صلاحية ممكنة، نسخًا احتياطية، حماية ملفات النظام، وإدارة وصول مناسبة. ACCDE يمكن أن يكون مفيدًا لتوزيع واجهة Access ومنع تعديل تصميم VBA في النسخة الموزعة، لكنه ليس حلًا أمنيًا مطلقًا.
